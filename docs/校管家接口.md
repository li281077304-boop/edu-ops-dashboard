# 校管家接口记录

## 已确认的接口形态

- 入口：`POST /api/report/QueryConsumeTotalPro`
- 预期 Content-Type：`application/x-www-form-urlencoded`
- 预期成功响应：JSON
- 认证：由已登录浏览器 context 的 Cookie jar 携带；项目不硬编码或保存 `WTwo-AuthToken`、`ASP.NET_SessionId` 等秘密。

## Chrome 只读实测（2026-09-13）

在当前登录状态下进入“报表中心 / 课消报表 / 课消汇总表”，清空 Network 后分别点击“查询”和“导出”：

### 查询

- 请求：`POST https://tms22.xiaogj.com/api/report/QueryConsumeTotalPro`
- 状态：`200 OK`
- 请求体：`application/x-www-form-urlencoded`
- 响应：`application/json; charset=utf-8`
- 关键字段形态：`sDate`、`eDate`、`campusids`、`dataType`、`sort`、`includeDullConsume`、`PageSize`、`PageIndex`，以及可选的 `Subject`、`Year`、`Term`、`Grade`、`Category`。
- 响应外壳：`PageSize/PageIndex/TotalCount/PageCount + Data.data[]`；`Data.data[]` 是按校区汇总的对象，包含 `rows`、`TotalUnit`、`TotalHours`、`TotalConsumeMoney`、`ConsumeCount`、`ConsumeStudentCount` 等字段。

这证明接口可以被复用，但这条接口返回的是**课消汇总**，不是逐节排课明细；它适合补充已发生的课消汇总指标，不能直接替代排课表来计算未来预排或逐节趋势。

### 导出

- 请求仍复用同一路径：`POST /api/report/QueryConsumeTotalPro`
- 请求体仍是表单，但额外带 `download=1`，并保留筛选字段。
- 响应：`200 OK`，`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，带附件文件名，Chrome 直接触发下载。

因此，查询与导出的分界字段已确认是 `download=1`；不需要依赖“先查询再导出”才能获得文件，但页面流程仍建议保留先查询用于人工核验。

### 鉴权

请求头中观察到排课接口还会由前端动态加入 `Wtwo-Authtoken`、`Wtwo-Companyid`；同时页面请求来自 `tms22.xiaogj.com`，接口位于 `next.xiaogj.com`，服务端允许带凭据的 CORS。实际自动化不应复制或硬编码这些值。

## 采集约束

`query_consume_total()` 接收外部传入的 Playwright `BrowserContext`，通过 `context.request.post()` 发请求。这样浏览器页面和 API request 共享会话，但认证生命周期仍由浏览器 context 管理。

仍需补测：过期登录、权限不足和空结果的错误形态。

不得把带 Cookie、Token 或学生明细的 HAR、截图、请求头提交到 Git。

## 排课列表 JSON 接口（已确认）

在“教务管理 / 排课管理 / 排课列表”设置人工月、展开筛选并点击“查询”后，Chrome 观察到：

- 请求：`POST https://next.xiaogj.com/api/course/Course/QueryNew`
- 请求体：JSON；日期字段为 `StartDate`、`EndDate`，分页字段为 `PageIndex`、`PageSize`，校区字段为 `CampusIDList`。
- 响应：`application/json; charset=utf-8`，外壳为 `IsSuccess`、`ErrorCode`、`ErrorMsg`、`TraceId` 和 `Data`。
- `Data` 包含 `TotalCount`、`PageSize`、`PageIndex`、`List`；`List` 为逐节排课明细，含 `StartTime`、`EndTime`、`Duration`（分钟）、`Status`、`CampusName`、`SubjectName`、`TeacherID`、`IsOneToOneName`、`CourseStudentCount`、`StudentCount_StudentAttendanceCount` 等字段。
- 前端当前按分页请求；项目适配器会捕获页面真实请求并自动翻页，不读取、不保存动态鉴权头。

项目入口：`edu-ops --collect-schedule-api`。它使用已登录浏览器页面触发查询并采集 JSON；失败时仍可使用 `--download-ui` 走 OOXML 导出兜底。

- 点击列表工具栏的无文字下拉按钮 → “导出排课”后，Chrome 下载了一个 OOXML 工作簿（扩展名为 `.xls`）。本地读取结果为 `1092` 行，日期范围 `2026-09-02` 至 `2026-09-27`，合计 `2182` 小时。

排课列表现在以 `Course/QueryNew` 作为优先主通道、UI 导出作为兜底；`Course/QueryTotal` 只承担页面合计辅助请求，不把它和本页的 `QueryConsumeTotalPro` 混为一谈。

## 自动化判断与风险

- 适合 Playwright：接口由页面触发、返回 JSON、字段稳定且可分页；采集器不需要接触凭据。
- 不建议把请求复制成长期固定的 `curl/fetch`：`Wtwo-Authtoken` 是动态值，登录过期、权限变化、前端版本切换都会导致失败。
- 主要脆弱点是菜单/筛选器文本改版、分页按钮或分页上限变化、跨域鉴权头变化，以及人工月配置错误。程序保留 UI 导出兜底，并对响应类型、数据日期范围和行数做校验。
- 排课明细含学生、教师、教室等敏感字段；原始 JSON 只能留在本地受控目录，不能提交 Git、上传 HAR 或写入日志。

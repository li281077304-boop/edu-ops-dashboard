# edu-ops-dashboard 验收清单

本清单区分“代码已完成”“已在真实页面验证”和“已上线运行”，避免把模板或单元测试误当成生产部署。

| 阶段 | 当前结论 | 证据 | 尚缺条件 |
|---|---|---|---|
| P0 工程骨架 | 已完成 | `pyproject.toml`、`src/`、测试、ruff、CI、Git 版本记录；跨系统边界契约已单独成文 | 无 |
| P1 UI 兜底 | 已完成首版 | Chrome 已验证人工月、展开筛选、清除默认结业条件、查询、导出；文件校验器现已强制检查关键列、有效日期和日期范围，并写入 JSONL 运行记录 | 页面改版时需更新选择器 |
| P2 API PoC | 已完成只读验证 | 课消接口查询返回 JSON、导出通过 `download=1` 返回 XLSX；排课 `Course/QueryNew` 返回 `IsSuccess + Data{TotalCount, PageSize, PageIndex, List}` | 过期登录、权限不足、空结果的错误形态仍需补测 |
| P3 标准数据层 | 已完成首版 | `ScheduleRecord` 同时兼容 QueryNew 字段与 Excel 字段；日期、分钟转小时、实到/应到解析、缺失维度 fail-closed 有测试 | canonical ID 映射由未来 adapter 完成；多学员明细是否拆分待业务确认 |

## 本机验收结果

```text
uv run pytest       38 passed
uv run ruff check . All checks passed
plutil -lint plist  OK
```

当前环境未发现 Docker/Podman/PostgreSQL/Metabase，因此以下真实服务 gate 没有被宣称为完成：

```text
REAL_POSTGRES_TESTED = NO
REAL_METABASE_TESTED = NO
REAL_SCHEDULER_TESTED = NO
Dashboard 自动刷新 = BLOCKED
生产 KPI 排除规则 = HUMAN_REQUIRED / BUSINESS_RULE_BLOCKED
```

部署时先执行：

```bash
docker compose -f infra/compose.yml up -d
```

再在 `edu_ops` 业务库执行两份迁移，最后用已登录的 Playwright storage state 运行 `--collect-schedule --write-metrics`。

# 运行与部署

## 本地人工月检查

```bash
uv sync --extra dev
uv run edu-ops --today 2026-09-13
```

## UI 兜底导出

```bash
uv sync --extra collector --extra excel
uv run edu-ops --download-ui --headed \
  --storage-state playwright/.auth/xiaogj.json
```

`storage-state` 由操作员在运行时提供，不能提交到 Git。若登录态失效，命令应失败并重新取得登录态；不要在脚本里填密码、Cookie 或 Token。

## 排课 JSON 主通道

```bash
uv sync --extra collector
uv run edu-ops --collect-schedule --headed \
  --storage-state playwright/.auth/xiaogj.json
```

该命令通过已登录页面触发 `Course/QueryNew`，自动按页面分页采集全量排课明细；接口失败时自动改用上面的 `--download-ui` 兜底。需要严格只跑 JSON 主通道时使用 `--collect-schedule-api`。launchd 模板可加 `--notify-on-failure`，在 API 和 UI 都失败时显示本机通知。

## 计算并写入指标

采集完成后，可显式提供周报中的分母，把五个指标一次性写入业务库：

```bash
uv run edu-ops --collect-schedule --write-metrics \
  --dsn 'postgresql://edu_ops:CHANGE_ME@127.0.0.1:5432/edu_ops' \
  --campus '宣城二校' --subject '数学' \
  --teacher-count 4 --total-subject-count 20
```

`--teacher-count` 只用于周平均课次，`--total-subject-count` 只用于平均课时；程序不会互相替代两个分母。

API 主通道失败时，编排器会记录失败原因并尝试 UI 兜底；两条通道都失败时以非零错误退出。`infra/scheduler/com.edu-ops-dashboard.example.plist` 是未加载的 launchd 模板，替换路径并确认登录态后再由操作员安装。

## API 主通道

API 入口需要由已登录的 Playwright context 调用，见 `src/edu_ops/collectors/xiaogj/api.py`。真实请求字段以 Chrome Network 观察结果为准，接口未确认前不把示例 Payload 当生产配置。

## PostgreSQL / Metabase

```bash
cp .env.example .env
# 编辑 .env，替换所有 change-me 值
docker compose -f infra/compose.yml up -d
```

首次启动新 PostgreSQL volume 时，初始化脚本会创建独立的 `metabase_app` 应用库和 `edu_ops` 业务库，并自动按顺序执行两份迁移。已有 volume 不会重复执行初始化脚本；升级或改密码前先按运维流程备份。原始 JSON/XLSX 不上传服务器。
